# v0.1.34 customer review

**Verdict: the infrastructure is serving the release, but Ask setup and billing
lifecycle are not complete product experiences.** This review adds L-291–L-299
to the [canonical kanban](kanban.md). Findings and fix details live there;
this document orders the work and defines how to accept it. No product code,
live settings, purchases, deployments or releases were changed in this review.

## What the customer failure actually was

The configured Gemini model was
`models/gemini-2.5-flash-native-audio-preview-12-2025`. The customer supplied the
provider's error: this model needs the Live API's bidirectional WebSocket
transport, whereas Lilypad sends chat-completions requests. Nonsecret installed
settings independently matched the selection. This is a model/transport
mismatch, not evidence that the API key is invalid or the backend is down.

The immediate recovery is to choose a currently available Gemini model that
supports text generation and tools, then run Save and test, optionally testing
images. A model being listed does not establish that it supports Ask. Do not
choose a Live/native-audio, TTS-only or embedding model for this adapter.
Do not promise a free quota for every listed model. The disclosed key should be
revoked and replaced; no key was copied into project notes or used by this
review to call a model.

Google documents both the [OpenAI-compatible endpoint](https://ai.google.dev/gemini-api/docs/openai)
and the separate [Live transport](https://ai.google.dev/api).
Its [model metadata](https://ai.google.dev/api/models) includes supported
methods. Use that metadata for initial suitability, followed by the existing
real tool-result round trip and image probe. Do not substitute a name-based
filter for capability verification.

## Implementation order for Claude

1. **Unblock Gemini first: L-291–L-293.** The customer should choose a provider,
   enter its credential, pick an appropriate model and reach a genuinely tested
   Ready state. Preserve a draft after failure. Distinguish authentication,
   unsupported model/transport, capability, network and quota failures. Keep a
   useful recovery action visible after reload.
2. **Repair billing as one coherent lifecycle: L-294–L-299.** Separate account
   ownership, subscription history, environment and effective entitlement.
   Preserve idempotency, handle concurrent client/webhook events transactionally,
   reconcile with Apple, and finish StoreKit only after entitlement delivery.
   Test reducer invariants first, then real Postgres races, then signed StoreKit
   purchase/restore/offline/relaunch scenarios. Do not switch on enforcement.
3. **Build the provider conformance suite below.** Every listed provider must
   earn its support status. Share safety and conversation invariants while
   keeping authentication and wire dialect in adapters. Do not put vendor names
   into the task runner or bypass approvals to improve benchmark success.
4. **Improve useful-task completion within existing M5 scope.** The current Ask
   surface opens apps/URLs, creates folders, reads AX, presses controls and can
   take screenshots. It does not expose general text entry or scrolling;
   screenshots alone do not make it a complete computer operator. Prioritize
   bounded text entry and navigation through existing input infrastructure,
   with focus/window binding, secure-field refusal, previews, cancellation and
   idempotency. Never restore scripts as a shortcut. The prompt also forbids
   questions although the finish schema has `needs_input`; design a deliberate
   clarification/resume flow using the shared protocol rather than asking the
   model to guess consequential missing details. Treat these as proposed M5
   improvements, not bugs proven by the Gemini error.
5. **Validate customer journeys, then cut.** Keep changes small enough to
   review. Record the exact source/build identifiers and actual outcomes.
   A green synthetic probe is necessary but a useful task on a signed Mac and
   phone is the acceptance test.

## Broad provider support contract

“All providers” is the product direction, not a claim that all APIs accept the
same request. A key authenticates one service; it does not adapt its transport,
model, tools, images or enterprise deployment contract. Never reject a key just
because its prefix is unfamiliar. Never silently send it or observations to a
different origin. Never turn failed tool support into unrestricted shell access.

| Provider family                                                     | Present implementation                                      | Required completion work                                                                                                                                                                                                                                   |
| ------------------------------------------------------------------- | ----------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Google AI Studio / Gemini                                           | Named preset through OpenAI compatibility                   | Filter by method/modality, normalize identifiers for the chosen API, model-specific output/reasoning budgets, preserve thought signatures, distinguish free-tier quota from incompatibility; verify a real two-turn task                                   |
| Anthropic                                                           | Native Messages adapter and named preset                    | Real available-model selection, tool-result continuation, image handling, refusal/truncation/rate-limit cases and any reasoning metadata required by supported models                                                                                      |
| OpenAI                                                              | Chat Completions adapter and named preset                   | Match model to supported API and token parameters; explicitly cover Responses-only capabilities with a separate adapter if offered. Do not assume every catalog id works with Chat Completions                                                             |
| OpenRouter                                                          | Named compatibility preset                                  | Vendor/model identifiers, capability metadata, required headers where applicable, endpoint-specific failures and round-trip metadata preservation                                                                                                          |
| Ollama / LM Studio / local compatible servers                       | Ollama preset and custom endpoint                           | Installed-model selection, empty catalog/startup help, tools/images verified per model, slow-loading progress, configurable bounded timeout and cancellation; no cloud fallback                                                                            |
| Other hosted compatible endpoints                                   | Custom endpoint only                                        | Add named presets only after conformance; support bounded, explicitly configured nonsecret headers where needed and protect sensitive headers. Validate actual dialect, not the word “compatible”                                                          |
| Azure OpenAI / Azure AI, Vertex AI, Bedrock and enterprise gateways | No dedicated enterprise adapters established by this review | Separate deployment/resource/API-version and authentication strategies, including scoped OAuth or signed requests where required. Secure token refresh and credential storage; never ask for an account password or pretend a bearer-key form is universal |

Expand supported services by passing these contracts, not by maintaining a
large logo list. Preserve custom endpoints as an advanced route with an honest
status. The current Gemini signature round-trip support already exists in
`ToolCall.extra`/`Block::ToolUse.extra`; preserve and extend it instead of
reimplementing it blindly. No live provider conformance was claimed here.

### Every adapter and named preset must pass

- Fresh setup, saved-key reuse, key rotation, removal, endpoint change and
  failed/late probe without overwriting newer settings.
- Catalog with mixed modalities, no models, retired models, pagination and a
  manually typed unknown id. Known unsupported choices explain the mismatch
  before making a generation request.
- One tool call, its result, and a second valid call; preserve opaque provider
  metadata. Handle multiple calls explicitly without silently discarding work.
- Tool schema errors, refusals, empty responses, output truncation, unsupported
  token parameters and reasoning budgets. Report the real condition instead
  of a generic “assistant stopped.” Never execute incomplete arguments.
- Optional synthetic image test; real screenshots only with the person's
  permission and only for the selected display. A failed image test must not
  silently change that permission.
- Invalid credentials, permissions, insufficient credits, temporary quota,
  5xx, redirect, oversized body, broken JSON and dropped connection. Bound the
  whole operation; surface waiting/retry state and keep Stop usable.
- A useful signed-device task with an observed result, safe approval re-check,
  denial, cancellation and human takeover. Include lower-cost/free-tier and
  local-model behavior without promising unlimited inference.

Use fixture servers and fault injection for the broad matrix. Real-provider
smokes need deliberately supplied credentials, synthetic content and a small
request budget; do not send private screenshots merely to certify a provider.
